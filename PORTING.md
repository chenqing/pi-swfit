# Pi Swift port — conventions

Historical porting notes follow. For the standalone release scope and subsequent fixes, see [Docs/UPSTREAM.md](Docs/UPSTREAM.md).

This package targets a faithful Swift port of `earendil-works/pi`, starting from upstream
commit `16f5f0af4`. It replaces `Vendor/PiLite`, which was a loose re-implementation and
was unstable (streams stopping/hanging). Unported surfaces are listed explicitly below.

## Incremental arguments and request identity — 2026-10-26

Selectively ported from upstream `d5b3de22d0e24a3e9c38a9410d3329b099717283`:

- `packages/ai/src/utils/streaming-json.ts`: incremental tolerant previews, immutable
  snapshots, bounded copy credit and strict final tool-argument validation. Anthropic,
  OpenAI Completions and Responses use one parser per call, including Responses final
  argument replacement. Grammar tool input appends deltas and reconciles the final input.
- `packages/ai/src/utils/identity.ts`: identity merging, attribution, explicit null disable,
  User-Agent formats and `withClientIdentity`, preserving mutable Models and request
  transforms. Agent, Models and the five supported provider APIs propagate identity.
  OpenCode session routing also recognizes custom providers using its endpoint.

This is not a package-wide 1.4.0 upgrade. `PI_AI_VERSION` remains `1.3.0`, the existing
PiAI baseline. Native detailed identity reports Swift rather than Node/Bun. Swift strings
are flat values, so open-string materialization also consumes snapshot credit; very large
previews can lag, while final arguments are exact. Change events defer a trailing UTF-16
high surrogate until its partner arrives, because Swift String cannot represent it alone.
The previous grammar helper signature and `getPiUserAgent()` remain compatibility shims.

Pagie additionally derives provider session IDs from the conversation and connection/model
fingerprint, so engine recreation and pool restart retain cache affinity. Requests without
a conversation ID still receive independent random IDs. This identifies the provider
conversation; it does not persist a running network request or guarantee a cache hit.

Validation uses isolated source copies and fake transports: upstream-recorded provider SSE,
1,105 snapshots generated by executing the pinned TypeScript parser, large JSON/grammar
inputs, Unicode splits, identity precedence and the app's multi-turn/restart request path.
No live provider billing, cache-hit-rate measurement or installed-app release is implied.

Targeted results: 75 PiAgent tests, 84 parser/provider/Models tests and 30 app request/session
tests passed. App tests compiled exact KnowledgeAgentKit/PagiePluginKit source copies in a
minimal Swift package, without building or installing the UI. Two existing compaction
cancellation assertions still expect `Compaction cancelled` but receive `This operation was
aborted`; both failures also reproduce with the pre-change source. They remain outside this
alignment batch.

## Resource and MCP expansion — native integration

Resource/configuration/skills, native extensions and MCP reference upstream
`42cb822f1c5d3153069dd0661bfd297424666cf1`; existing PiAI/PiAgent baseline stays
`16f5f0af4`. This is not a whole-package version bump. Source blobs are pinned in
`Docs/upstream-reference.json`. Validation and explicit limits are in
`Docs/UPSTREAM.md`.

Implemented: scoped settings, YAML skills, native extension commands/input/context/lifecycle,
revocable dynamic registrations, nested calls, all four MCP exposures, tool_search,
sandboxed JavaScriptCore codemode, aggregated resources, stdio/HTTP and OAuth.
Pagie owns AgentSession instances and supplies native configuration, project trust,
per-call MCP approval, Keychain credentials and document-scoped tool bindings.
The former app-owned PagieSession loop is replaced by the SDK, with a reading-specific
compaction strategy injected through setCompactionHandler.

Swift adaptations include actor-owned transports, process groups, ordered JSON,
directory-lock-compatible atomic config edits and cycle-safe bounded skill traversal.
MCP and OAuth credential requests do not automatically redirect; an explicit 401 may
refresh and retry once, but an uncertain network failure is never replayed. MCP is
host opt-in. shutdown() awaits cleanup; dispose() immediately revokes tool handles.
Direct steer/followUp now throw if extension processing fails or the session is closing.

HTTP SSE now resumes interrupted responses with a per-stream Last-Event-ID, honors server
retry timing, and bounds retries with exponential backoff when no timing is supplied. No
uncertain tool POST is replayed. Startup and turn preparation wait at most startupWaitMs
(default 1 second); other connections continue in the background. Dropped connections
are re-established on the next user turn, after withdrawing stale tool handles. This is a
Swift adaptation: a previously captured tool handle remains revoked, unlike upstream's
call-time reconnection. Failed/disabled/needs-auth servers require explicit user action.
Logout also cancels a pending OAuth loopback login.

The pinned official MCP conformance matrix has run against the Swift client: 26 scenarios,
261 passing checks, 8 known failures matching upstream, no regressions. See
Conformance/README.md and the independently generated Conformance/swift-results.json.
This does not certify protocol 2026-07-28, real third-party accounts or all upstream APIs.

Not claimed: arbitrary TypeScript/npm execution, npm/git package installation, the whole
upstream ExtensionAPI/provider-registration surface or minimatch extglob/brace syntax.
`auth.provider` requires an explicit host binding. Native extension reload rebinds existing
Swift handlers; it does not dynamically compile Swift source. No general network or file
API is available inside codemode. The helper is macOS-only; iOS cannot spawn stdio tools.

## Layout

One target per upstream package; one Swift file per upstream file, same relative path, `.ts` -> `.swift`:

| Target | Upstream |
|---|---|
| `Sources/PiAI/...` | `packages/ai/src/...` (e.g. `api/anthropic-messages.swift`) |
| `Sources/PiAgent/...` | `packages/agent/src/...` |
| `Sources/PiMCP/...` | `packages/mcp/src/...` (client/transports subset) |
| `Sources/PiCodingAgent/...` | `packages/coding-agent/src/core/...` (session, settings, skills/resources; partial SDK) |

Swift-only infrastructure lives in `Sources/PiAI/platform/` (JSON, fetch, abort, locks, SDK cores).

Pinned SDK sources (read-only reference, never executed) are in `/tmp/pi-sdk/`:
`openai-7.19.0`, `anthropic-ai-sdk-0.129.0`, `google-genai-2.21.0`, `partial-json-0.1.7`.
Where upstream calls an SDK, port the SDK behavior that matters (request building, headers,
retries, timeouts, SSE parsing, error classes and their exact message text) into Swift.

## Translation rules

- **Names are upstream names.** Functions, types, properties, constants and error messages keep the
  TS spelling (`streamSimple`, `transformMessages`, `isContextOverflow`, `DEFAULT_THINKING_BUDGETS`).
  Port every function in the file, exported or not, in the same order, with the same comments.
  Do not "simplify" logic, merge branches, or drop edge cases. If something truly cannot apply
  (Node-only APIs such as `process.env` file reads, proxies, telemetry spans, `bun` paths),
  keep a stub or comment `// Not ported: <reason>` at that place.
- **Types**: `interface` -> `struct` (Sendable); union of object shapes -> `enum` with associated
  values; string-literal unions that upstream extends with `(string & {})` -> `String`. Optional
  fields -> optionals. Integer token counts / timestamps -> `Int`; money -> `Double`.
- **JSON**: `JsonValue` / `JsonObject` (ordered; `platform/JsonValue.swift`). Request bodies are
  built as `JsonObject` in the **same key order as the upstream object literal** — request bytes
  must be stable for prompt caching. `JSON.stringify(x)` -> `x.serialized()`.
  `undefined` fields are omitted (do not write `null` unless upstream writes null).
- **Async**: upstream `(async () => { ... })()` producers -> `Task { ... }`. Upstream `await` stays
  `await`. Callbacks that upstream may `await` are `async` closures.
- **Abort**: upstream `AbortSignal` -> `AbortSignal` (`platform/AbortController.swift`, same API:
  `aborted`, `reason`, `throwIfAborted()`, `addEventListener`, `AbortSignal.any`, `AbortSignal.timeout`).
  Never rely on Swift task cancellation alone; check the signal where upstream does.
- **HTTP**: `fetch` -> `FetchFunction` (`platform/Fetch.swift`): `FetchRequest` / `FetchResponse` with a
  streaming `ResponseBody` (async sequence of `Data`). Use `options.fetch ?? defaultFetch`.
- **Streams**: `EventStream` / `AssistantMessageEventStream` (`utils/event-stream.swift`) — same
  `push` / `end` / `result()` contract. Event `partial` is a value snapshot of the output so far
  (upstream shares a live object); push `partial: output` after mutating `output`.
- **Errors**: `new Error(msg)` -> `PiError(msg)`; `error instanceof Error ? error.message : String(error)`
  -> `errorMessage(error)`. Keep upstream error message text byte-for-byte: the retry/overflow
  classifiers match on it.
- **Time**: `Date.now()` -> `dateNow()` (Int ms); `performance.now()` -> `performanceNow()`.
- **Mutation of content blocks**: `AssistantContent` is an enum; mutate via index
  (`if case .text(var t) = output.content[i] { t.text += d; output.content[i] = .text(t) }`).
  Provider-local scratch state (e.g. `partialJson`, block `index`) goes in a side table, never into
  the persisted message.
- Swift 6 language mode, strict concurrency, **zero warnings**.

## Tests

Port the upstream unit tests that exercise the ported file (`packages/*/test/...`) to Swift
Testing (`import Testing`) under `Tests/<Target>Tests/`, same file names. Tests that need the
network or a real provider key are skipped. Use fake `FetchFunction`s that replay SSE bytes.
